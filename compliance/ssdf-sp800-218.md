# NIST SSDF (SP 800-218 v1.1) practice mapping

How LicenseForge is built, practice by practice, with the evidence in this repository. US federal buyers ask suppliers to attest to the SSDF (CISA secure software self-attestation). Signing that attestation is a v0.3 Roadmap item; this file is its groundwork. Status uses the terms of the [control matrix](nist-800-53-matrix.md), plus *not started*: no code, process or Roadmap item yet. GitHub settings were checked on 2026-11-04.

| Practice | Status | How | Evidence | Gaps |
|---|---|---|---|---|
| **PO.1** Define security requirements | implemented | Security requirements are recorded as ADRs (tenancy, authorization, crypto, audit, compliance) before code is written; the license format has a spec | [ADR index](../docs/adr/README.md), [ADR-0024](../docs/adr/0024-hipaa-nist-and-fedramp-readiness-from-day-1.md), [license format](../spec/license-format.md) | – |
| **PO.2** Roles and responsibilities | partial | Maintainers own every path, and the security-sensitive paths are listed separately | [CODEOWNERS](../.github/CODEOWNERS) | Single maintainer; no second reviewer yet |
| **PO.3** Supporting toolchains | implemented | The Go version is pinned in `go.mod`; linters are configured in the repo; CI Actions are pinned by commit SHA and images by digest; Dependabot updates both | [go.mod](../go.mod), [.golangci.yml](../.golangci.yml), [ci.yml](../.github/workflows/ci.yml), [dependabot.yml](../.github/dependabot.yml) | – |
| **PO.4** Criteria for security checks | implemented | Required checks on `main`: `go` (format, vet, generated code, migrations, tests, FIPS tests, lint, build), `dco` and `analyze` (CodeQL). The tenant-isolation tests are release-blocking (ADR-0009) | Ruleset [`main`](https://github.com/licenseforge/licenseforge/rules/26381884), [ci.yml](../.github/workflows/ci.yml) | The `Merge gate` check isn't in the required list |
| **PO.5** Secure environments | partial | CI jobs get least-privilege tokens (`contents: read` by default); the DCO and Scorecard jobs check out without persisted credentials. Secret scanning and push protection are on | [dco.yml](../.github/workflows/dco.yml), [scorecard.yml](../.github/workflows/scorecard.yml) | No hardened or ephemeral self-hosted runners (GitHub-hosted only) |
| **PS.1** Protect code from tampering | partial | `main` accepts changes only through pull requests: deletion and force pushes are blocked, required checks must pass and review threads must be resolved. Every commit is signed off (DCO; PRs opened by Dependabot excepted). Commits on `main` since the initial commit are GitHub-signed squash merges, by practice (not enforced) | Ruleset [`main`](https://github.com/licenseforge/licenseforge/rules/26381884), [dco.yml](../.github/workflows/dco.yml) | Signed commits aren't required; 0 approvals and no code-owner review required; organization admins can bypass the ruleset on pull requests; merge, squash and rebase are all allowed |
| **PS.2** Release integrity verification | planned | cosign signatures for images, chart and SDKs (ADR-0021) | – | No release pipeline yet (Roadmap v0.1: signed releases + SBOM + SLSA provenance) |
| **PS.3** Archive and protect releases | planned | SBOM and SLSA provenance kept with each release | – | As PS.2 |
| **PW.1** Secure design | implemented | Threats are addressed in ADRs: tenant isolation with RLS as a backstop (ADR-0009), separate database logins (ADR-0009, ADR-0029), signing key lifecycle (ADR-0026), clock tampering (ADR-0018) | [ADR-0009](../docs/adr/0009-multi-tenancy.md), [ADR-0029](../docs/adr/0029-identity-tables-and-tenancy.md) | – |
| **PW.2** Review the design | implemented | ADRs record context, decision and alternatives, and several were amended after a security review (e.g. ADR-0009's database role model). Accepted ADRs are immutable and change only through a new ADR | [ADR-0001](../docs/adr/0001-record-architecture-decisions.md), [CONTRIBUTING.md](../CONTRIBUTING.md) | – |
| **PW.4** Reuse well-secured software | implemented | Stdlib crypto only (FIPS-capable Go module), with no hand-rolled primitives. The few dependencies are well known (ent, pgx, go-oidc, x/oauth2) | [go.mod](../go.mod), [ADR-0021](../docs/adr/0021-certification-readiness.md) | – |
| **PW.5** Secure coding practices | implemented | Parameterized SQL only, input checked before any query, fail-closed defaults; golangci-lint enforced in CI | [.golangci.yml](../.golangci.yml), [control matrix SI-10](nist-800-53-matrix.md) | – |
| **PW.6** Secure build configuration | implemented | Static `CGO_ENABLED=0` builds with `-trimpath`; FIPS builds with `GOFIPS140=certified`; distroless non-root image | [Makefile](../Makefile), [Dockerfile](../Dockerfile) | Builds aren't reproducible-verified yet |
| **PW.7** Review and analyze code | partial | Every change is a pull request with resolved threads; CodeQL on every PR and weekly; go vet and golangci-lint | [codeql.yml](../.github/workflows/codeql.yml), [ci.yml](../.github/workflows/ci.yml) | The ruleset requires no approval and no code-owner review (single maintainer), and organization admins can bypass it |
| **PW.8** Test executable code | implemented | Unit and PostgreSQL integration tests with `-race`, the whole suite again in FIPS 140-3 mode, and SDK tests on Windows. Conformance vectors cover the license format, claims and fingerprints. The CI chart job renders the Helm chart and checks that bad values fail | [ci.yml](../.github/workflows/ci.yml), [spec/vectors](../spec/vectors/lf1.json) | No fuzzing yet |
| **PW.9** Secure defaults | implemented | Chart defaults: Pod Security restricted, NetworkPolicies on, no service account token. The server refuses unsafe database logins and the owner login | [Secure Configuration Guide](secure-configuration-guide.md) | – |
| **RV.1** Identify vulnerabilities | partial | Private reporting (GitHub advisories, security@licenseforge.io); CodeQL, Dependabot alerts, secret scanning and OpenSSF Scorecard | [SECURITY.md](../SECURITY.md), [scorecard.yml](../.github/workflows/scorecard.yml) | No govulncheck or image scanning in CI |
| **RV.2** Assess and remediate | partial | Remediation targets by severity: Critical and High 30 days, Moderate 90, Low 180; fixes ship as GitHub Security Advisories | [SECURITY.md](../SECURITY.md) | No release pipeline in main yet, so fixed versions can't be published as releases |
| **RV.3** Root cause analysis | not started | – | – | No written process and no Roadmap item. Intended: each advisory's fix adds a regression test, and recurring classes become an ADR or a lint rule |
