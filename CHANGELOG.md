# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]
### Fixed
- `TestActivationRateLimitIgnoresUnknownKeys` no longer fails when a minute boundary falls mid-test: it runs the limiter on a fixed clock.
- Signing keys: `signing.Local` `Create`, `Promote` and `Discard` now require `key:write` (owners, ADR-0019) on the whole tenant, in the tenant they act on; other roles, `sdk` and admin tokens, product-scoped principals, another tenant's principal and calls without a principal get `authz.ErrDenied` and change nothing.

### Added
- Per-tenant MFA policy, step 2 (ADR-0038): every tenant request from a session checks its assurance against the tenant's policy right after the membership check (non-members still get 404); a member falling short gets `403 mfa_required` with `required_assurance`, `session_assurance` and a `step_up_url`, audited once per session and tenant (`session.mfa_required`) and counted in `licenseforge_mfa_refusals_total`. Creating API tokens therefore needs a qualifying session; tokens are exempt at use. `GET /me/tenants` adds `mfa_policy` and `accessible`. Migration `20261105160000_tenant_mfa_enforce_security.sql` (the login path reads the policy).
- Tenant audit log read API (ADR-0027, ADR-0036): `GET /api/v1/tenants/{tenant}/audit-events`, for the dashboard's audit viewer and tenant self-export. Paged by `seq`: newest first, or oldest first from `after_seq` (cursor carries the direction). Every AU-3 field plus `seq`, `prev_hash` and `hash`, the SIEM export's fields, `details` byte for byte as hashed, so a tenant can verify its chain. Needs `audit:read` on every product (owners and admins). Served from the tenant pool under RLS (never the platform chain). Each read is audited as `audit_event.read` in the read's transaction (no entry, no data), at most once per reader per 15 minutes, checked again under the chain's lock so concurrent reads record one; refusals are recorded as denied. `occurred_at` is sent in the hashed form (six fractional digits) and the hash is documented in the spec, so a chain can be verified from the response alone. Every API response now carries `X-Content-Type-Options: nosniff`.
- Go SDK online client, `sdk/go/online` (ADR-0004, ADR-0018, ADR-0034): `Activate` (one random `Idempotency-Key` across retries), `Refresh`, `Deactivate` against the activation API; every lease verified with `licensefile` (signature, claims at its `iat`, product, fingerprint, tenant, no older than the held one) before it is used or cached; `Current` checks the cached lease at max(local, server-adjusted) time and through the optional clock guard, which each lease's `iat` resets; `Run` refreshes from `refresh_after` in server time, earlier when a fast local clock would lapse the lease locally first, and no later than half the time left to `exp` and `iat + max_offline` (never sooner than `MinRefreshInterval` after a success, without polling when a refresh can't help) with backoff, jitter and `Retry-After`, and forgets the lease on revocation or a moved seat; https-only base URLs (http only for loopback) and no redirects with the default client; `Forget` (recovery from a far-future `iat`); non-fatal problems through `Warnings` and `Run`'s callback; `ClockTolerance` and `BuildDate` (`updates_until`) in the claim checks; stable error codes as typed errors; a pluggable lease `Store` interface. `sdk/go/README.md`.
- Activation management API for the dashboard (ADR-0019, ADR-0032, ADR-0034): `GET /tenants/{tenant}/licenses/{id}/activations` (cursor, newest first, deactivated ones included; `activation:read` on the license's product) and `POST …/activations/{activation_id}/deactivate` (`activation:manage`, so support and up; frees the seat under the same license lock and update as the SDK's deactivate; audited as `activation.deactivate` with the user or token as actor, refusals too; an already deactivated activation answers 200 unchanged). A hidden license answers 404 like a missing one. The License view gains `active_activations`, the seats taken now.
- Audit retention (ADR-0036, part 2 of 2). `licenseforge audit prune` runs as a Helm CronJob (`auditRetention.*`, `concurrencyPolicy: Forbid`) with the `licenseforge_pruner` login. It cuts each chain's prefix of entries older than its retention period, in batches of 10,000, each behind an anchor. A cut never includes the chain's last entry or anything a registered export sink hasn't delivered (a missing cursor counts as 0). A delete count that doesn't match the cut rolls the batch back, and each cut is recorded as a chained `audit.retention` entry. Retention comes from `tenants.audit_retention_days` (owners only via `retention.SetTenantRetention`, 365 to 36,500 days, audited, refusals included) and `LICENSEFORGE_PLATFORM_AUDIT_RETENTION_DAYS` for the platform chain. **Upgrading: create the `licenseforge_retention` role before `licenseforge migrate`** (Secure Configuration Guide). Migrations `20261105023832_audit_retention.sql` and `20261105023833_audit_retention_security.sql`.
- Dashboard overview at `/t/{slug}` (ADR-0020).
  - Licenses by status and active customers, from one `GET /summary` request. The customers tile appears only when the summary includes customers.
  - The newest licenses, with product and customer names.
  - Activations, failures and recent audit activity wait for their APIs.
- `GET /api/v1/tenants/{tenant}/summary` (ADR-0020, ADR-0032): exact counts for the dashboard overview.
  - Licenses by status (one GROUP BY under RLS), in the caller's product scope.
  - Active customers, present only for callers with `customer:read` on every product.
  - Each counter is an object, so counters (for example activations) can be added without breaking clients. Lists still carry no totals.
  - `licenses.Service.Counts` and `customers.Service.CountActive`.
- Dashboard licenses screen at `/t/{slug}/licenses` (ADR-0020).
  - The list filters by product, customer and status, and shows key hints, never keys.
  - The details show the entitlement snapshot and dates. Suspend and revoke ask for confirmation, and revoke says it is final; reinstate doesn't ask.
  - Issuing a license (product, customer, plan ID, type, external references) sends an `Idempotency-Key`, so a retry never issues twice: it is kept after a network error, a 5xx or an idempotency conflict, and replaced after a definitive 4xx (a fixable form error). Archived customers aren't offered, and a caller who can't list customers enters a customer ID. The web lint refuses `console` calls, so secrets can't be logged. The key is shown once and kept only in the dialog.
  - Actions are hidden below manager.
  - Activations aren't shown yet: the API has no management endpoints for them.
- Per-tenant MFA policy, step 1 (ADR-0038): every dashboard session records the ID token's `amr`, `acr`, `acrs` and `auth_time` and a computed assurance (`none`, `mfa`, `phishing_resistant`; configurable `LICENSEFORGE_OIDC_*_AMR` / `_ACR` sets, `pwd`, `sms`, `tel` never count; missing claims mean none), also in the login's audit entry. `tenants.mfa_policy` with `PATCH /api/v1/tenants/{tenant}` for owners from a session: raising it needs a session that already meets it (409 `mfa_policy_unmet`), audited as `tenant.mfa_policy.update`, and the answer reports the active API tokens (not revoked). Enforcement and step-up login follow. **Migration** `20261105051158_tenant_mfa.sql`.
- Dashboard products and customers screens (ADR-0020), at `/t/{slug}/products` and `/t/{slug}/customers`.
  - Products: list (a product-scoped caller sees only its products), create (slug and name; the slug is immutable) and rename (JSON Merge Patch).
  - Customers: list, create (with `key=value` external references), edit name, email and external references (JSON Merge Patch that sends only the changes: an emptied email and a removed reference are sent as `null`, and untouched references are left out), and archive with a confirmation.
  - Actions the caller's role can't perform are hidden: product create needs admin with every product, rename admin, and customer changes manager with every product. The API stays the real check.
- OTLP audit export (ADR-0036): every audit chain goes as OTLP logs over HTTP with the JSON encoding, hand-written with no OpenTelemetry dependency. Each record carries `lf.audit.*` attributes: every AU-3 field plus seq, prev_hash and hash. TLS 1.2+, verified, optional mTLS, optional headers. A batch counts as delivered only on a 2xx that rejects no record (`partialSuccess`); redirects aren't followed. Configured with `LICENSEFORGE_AUDIT_OTLP_*` or the chart's `audit.export.otlp.*`; it can run alongside syslog, each with its own cursors.
- Catalog API slice 1 (ADR-0015, ADR-0019, ADR-0032): products (`internal/catalog`: list, get, create, rename by merge patch; product-scoped, a hidden product answers like a missing one; creating needs `catalog:write` on every product; a taken slug is 409) and customers (`internal/customers`: list, get, create, merge patch with a nullable email, archive once; tenant-wide, managers and up write; audit details without names, emails or refs). `apitokens.Revoke` re-checks the caller's membership first in its transaction.
- Dashboard members and invitations screen at `/t/{slug}/settings/members` (ADR-0020, ADR-0035).
  - Members: role changes use a JSON Merge Patch. A confirmation previews the API tokens and pending invitations the change would revoke (mirroring the server's rules, from the token and invitation lists), with a toggle for each, and the result shows the IDs actually revoked.
  - Removal works the same way (the IDs come from the `X-Revoked-*` headers).
  - Invitations: list, create (the invite link is shown once and kept only in the dialog) and revoke.
  - Accept page `/invite`: the token travels in the URL fragment (`#token=`), so it never reaches server logs. It is removed from the address bar, kept in the tab's sessionStorage only across the sign-in round trip, and sent in the POST body.
  - Only roles the caller may assign are offered.
  - The role select sits in the confirmation dialog, which waits for its preview. A preview that can't load turns both revoke toggles off, and an incomplete one says so. Tokens above the caller's role are marked, because the server would refuse their revocation. Accept can be retried after any error except a refusal.
- Audit retention groundwork (ADR-0036, part 1 of 2). `audit_anchors` is insert-only: an anchor must name a real entry by seq and hash and move its chain's start forward. A fifth login, `licenseforge_pruner` (group `licenseforge_retention`), is the only one that may delete audit entries, and the database lets it delete only entries at least 365 days old and at or below the chain's newest anchor. It may append only `audit.retention` entries and reads the export registry and cursors. `store.OpenRetention` checks it like the serving logins, and `serve` refuses `LICENSEFORGE_RETENTION_DATABASE_URL`. `audit.Verify` now starts at the stored anchor. **Upgrading: create the `licenseforge_retention` group role before `licenseforge migrate`** (see `deploy/database-setup.sql`). Migrations `20261105014358_audit_anchors.sql` and `_security.sql`.
- `TestSigningKeysInDatabase` uses fresh key IDs, so it passes when run again on the same database.
- Per-client-address rate limit on the public listener, before anything else (ADR-0032 step 0, `internal/ratelimit`): fixed one-minute windows per address (IPv6 per /64) and surface, with defaults of 1200/min for the activation API, 600/min for the rest of `/api/v1` and `/auth/`, and 60/min for `/auth/login` and `/auth/callback` (`LICENSEFORGE_RATE_LIMIT_ACTIVATION`, `_MANAGEMENT`, `_LOGIN`; `0` = off). Over quota, the answer is 429 problem+json with `Retry-After` and `RateLimit-Policy` / `RateLimit`. At most 100,000 addresses are tracked per window; past that, new addresses pass untracked (fail open, counted). `LICENSEFORGE_TRUSTED_PROXIES` (Helm `trustedProxies`; prefixes broader than /8 or /32 refused) lets the server take the client from `X-Forwarded-For` (right-most untrusted hop), also for login audit entries; a header from an untrusted peer is ignored, counted (`licenseforge_forwarded_headers_ignored_total`) and logged once, and the chart's install notes warn while `trustedProxies` is empty. Paths are classified as decoded, never cleaned, the way ServeMux routes them, so encoded dot segments can't skip the limit. Metrics: `licenseforge_rate_limited_requests_total` and `licenseforge_rate_limit_untracked_requests_total` by surface. The server now has a 30 s read timeout and a 60 s write timeout.
- Audit export to a SIEM over syslog (ADR-0036): RFC 5424 messages over TLS with RFC 5425 octet framing, TLS 1.2+, certificate verification always on, optional mTLS. Every field is a strictly escaped SD-PARAM, including seq, prev_hash and hash. Each batch uses its own connection and counts as delivered only after the collector's `close_notify`; a plain TCP close is not delivery (detected as an EOF on the raw connection, which crypto/tls never reads after a `close_notify`). The CA file is re-read for every batch and the client certificate at every handshake, so rotated Secrets apply without a restart. Configured with `LICENSEFORGE_AUDIT_SYSLOG_*` (bad settings stop the server at start); the sink is registered before serving. Chart: `audit.export.syslog.*` (CA and client certificate from Secrets, one NetworkPolicy egress rule). Export sends now get half the lease measured from the claim.
- Audit export core (ADR-0036), `internal/auditexport`, with no sink yet (syslog follows). It adds an `audit_export_sinks` registry and one `audit_export_cursors` row per sink and chain, on the platform pool only. A replica leases a chain's cursor (`claimed_by`/`claimed_until`, a short transaction with `SKIP LOCKED`), sends the next batch outside any transaction, and advances only while it still holds the lease at the same position. Delivery is at-least-once and gap-free per chain. The database lets a cursor start only at 0 and move only forward to an existing entry. Metrics: `licenseforge_audit_export_failures_total{sink}` and `licenseforge_audit_export_lag_seconds{sink}`. Migrations `20261105001846_audit_export.sql` and `_security.sql`.
- Audit verification in pages (ADR-0036): `audit.Verify(ctx, run, tenantID, from)` reads keyset pages of 1,000, one short read-only transaction each. The anchor and the first page come from one REPEATABLE READ snapshot. It resumes from a head the caller verified earlier (checking that entry is unchanged), so a periodic check only reads new entries. A break at the start or at a page boundary re-reads the anchor and restarts once if a prune moved it; anchors themselves come with retention. `store.DB.ReadPlatform` and `ReadTenant` are its runners. Metrics: `licenseforge_audit_write_failures_total{chain}` (tenant or platform) and `licenseforge_audit_verify_failures_total`.
- Activation HTTP API for SDKs (ADR-0004, ADR-0034): `POST /api/v1/activation/tenants/{tenant}/activate`, `/refresh` and `/deactivate`, authenticated by `Authorization: License <key>` (never a token or session; only on the API host when `LICENSEFORGE_API_HOST` is set). Activate accepts `Idempotency-Key` (ADR-0032; the license is the credential, refusals are stored with their audit entry, a replay reruns the license checks). Per-license-key rate limit, in process and per replica: 60 requests a minute, 429 with `Retry-After`, `RateLimit-Policy` and `RateLimit`. Stable problem codes (`license_suspended`, `license_revoked`, `license_expired`, `activation_limit_reached`, `rehost_limit_reached`, `binding_mismatch`, `not_activated`, `rate_limited`). Migration `20261105001019_activation_api.sql`: a non-partial `activations (license_id, fingerprint)` index for the seat-move history, and license IDs allowed as idempotency credentials.
- License endpoints (ADR-0013, ADR-0032): `GET /tenants/{tenant}/licenses` (cursor, newest first; `product_id`, `customer_id`, `status`, `created_after` / `created_before` filters; silently limited to the caller's product scope), `GET …/licenses/{id}`, `POST …/licenses` (the license key returned once; with `Idempotency-Key` through `internal/idempotency`, a retry gets the stored answer after the product and permission checks pass again), and `POST …/{id}/suspend`, `/reinstate`, `/revoke` (200 with the license; 409 `invalid_state`). `internal/licenses`: field errors as JSON Pointers (`InvalidError`), value checks after the product and permission checks, `IssueTx` and `RecheckIssue` for idempotent issue, `List` and `Get`.
- `GET /api/v1/me/tenants` (ADR-0020, ADR-0032) lists the signed-in user's tenants: tenant ID, slug, name, role and product scope, sorted by slug, in one page. It is session only and is a user route like accepting an invitation (API tokens get 401). The dashboard's tenant switcher and its role and scope checks now use it instead of a stub.
- Container images and release binaries embed the dashboard (ADR-0020). The Dockerfile has a Node 24 stage (pinned by digest, on the build platform, `npm ci` from the lockfile with no install scripts) whose `web/dist` the Go stage embeds with `-tags webui`; the standard and FIPS images both have it. The release workflow builds the bundle before the binaries (`make web`, `TAGS=webui`), and its dry run fails if any binary or image (amd64 and arm64, standard and FIPS) lacks the dashboard or its notices, or carries the placeholder page. The npm packages in the bundle (the lockfile's production dependencies plus Tailwind, whose CSS ships) are merged into every image and binary SBOM. The bundle ships `THIRD_PARTY_NOTICES.txt` (served at `/THIRD_PARTY_NOTICES.txt`) with each package's license and license files, or the standard SPDX text of its license when a package ships none.
- Invitation endpoints (ADR-0019, ADR-0029, ADR-0032), `internal/invitations`: list (cursor, newest first, never the link token), create (the link token returned once; open 7 days; the role can't exceed the inviter's, re-checked in the transaction), revoke (open invitations only), and the session-only `POST /api/v1/invitations/accept` outside any tenant path (`store.AcceptInvitation`; every reason it can't be accepted answers the same 422). Every change and refusal audited, without emails. Pending invitations follow their inviter's access (ADR-0035 extended): removing a member, or a demotion or narrower scope, revokes by default the member's pending invitations the change newly excludes (`revoke_invitations=false` keeps them; PATCH `revoked_invitation_ids`, DELETE `X-Revoked-Invitation-Ids`). The audit helpers shared by API tokens, members and invitations move to `audit.By` and `audit.Refused`.
- Prometheus metrics (`internal/metrics`, private registry) on their own listener, `LICENSEFORGE_METRICS_ADDR` (default `:9090`), never on the public one. They cover: HTTP requests and durations by route pattern and status class; Go runtime and process; connection pool stats for the tenant, platform and identity pools; dashboard logins by outcome; and activations, lease refreshes (success, denied for a valid key refused, failure) and unknown license keys from `internal/activations`. API requests carry the API route pattern. Label values come only from fixed sets: no tenants, users, keys or raw paths. Chart: a `metrics` container and Service port (`metrics.port`), NetworkPolicy ingress on it only from `metrics.scrapeFrom` (default: the `monitoring` namespace; empty: closed), an optional ServiceMonitor, and `values.schema.json` for `metrics.*`. New dependency: `github.com/prometheus/client_golang`.
- Idempotency-Key store (ADR-0032), `internal/idempotency`: tenant table `idempotency_keys` (forced RLS; claimed empty and completed once in the operation's own transaction, deleted only after 24 hours), scoped to (tenant, credential), request hash over the resolved tenant ID, operation, path parameter IDs and body; stored response bodies encrypted with the keyring, bound to their row; the platform pool sees only `id` and `created_at`. `Store.Do` replays a stored 2xx/4xx outcome after re-running the caller's checks, refuses a reused key with another request (`ErrKeyReused`) and a request still in flight past a bounded wait (`ErrInProgress`); 5xx and failures roll back with the operation and leave no key. `Cleanup` deletes expired keys across tenants. **Migration**.
- Dashboard API tokens screen at `/t/{slug}/settings/api-tokens` (ADR-0020). The list uses "load more" cursor pagination. Creating a token shows its secret once, with a copy button and a warning; the secret is held only in the dialog's state, never in the query or mutation cache or in storage. Revoking asks for confirmation. Errors are shown by problem `code`, with field errors mapped from JSON Pointers. Roles the user can't assign are hidden (the API still checks). Dialogs are native `<dialog>` elements, which keeps the strict CSP. The dashboard's `/api/v1` client is generated from `api/openapi.yaml` by `openapi-typescript` with `openapi-fetch` (`npm run gen:api`, committed, checked for staleness in the `Web` workflow). One fetch wrapper adds same-origin credentials and the session's CSRF token to every request. New frontend dependencies: `openapi-fetch` (runtime), `openapi-typescript` and `jsdom` (dev).
- Session controls and login banner (ADR-0024, AC-12 and AC-8). `LICENSEFORGE_SESSION_IDLE_TIMEOUT` (default 1h) and `LICENSEFORGE_SESSION_MAX_AGE` (default 12h) configure dashboard sessions. Values are checked at start: idle at least 5m, max age 1h to 24h (the database cap) and at least the idle timeout. The session cookie's Max-Age follows the max age, and the management API's session checks (`/api/v1`) use the same timeouts. `LICENSEFORGE_LOGIN_BANNER` is a plain-text notice of up to 4 KB, UTF-8 with no control characters except newline and tab, and no format characters or line/paragraph separators (bidi overrides, zero-width characters). `GET /auth/config` serves it without authentication as `{banner, banner_id}`, revalidated on every load (`no-cache` with the banner ID as ETag). `/login` shows it as text, and the button works only after "I agree". With a banner configured, `/auth/login` requires `?banner=<banner_id>`. The acknowledged ID travels in the login flow cookie, and the callback refuses a login whose ID isn't the current banner's, redirecting to `/login?banner_changed=1`. Each completed login logs `login banner acknowledged` with the user and the acknowledged banner ID as AC-8 evidence. In `compliance/`, AC-8, AC-12, IA-11 and HIPAA 164.312(a)(2)(iii) are now marked implemented, and the Secure Configuration Guide covers the new settings. `identity.IdleTimeout` and `AbsoluteTimeout` are replaced by `identity.Service` fields with `DefaultIdleTimeout` and `DefaultMaxAge`.
- `internal/activations` (ADR-0004, ADR-0013, ADR-0017, ADR-0025): online activate, refresh and deactivate, authenticated by license key (lookup hash, then decrypt and constant-time compare) under the URL's tenant. Activate checks status, expiry and binding, reuses an active activation of the same fingerprint, counts seats under a row lock, and starts a `from_first_activation` term on the database clock; every grant is a signed lf1 lease (ADR-0034: exp from `lease_seconds`, capped at the license's expiry; `refresh_after` at half of min(lease, `max_offline`); grace only in the term's last lease, and refreshes of existing activations during grace; `max_offline`, binding and the entitlement snapshot). Seat moves to new machines count in `rehost_count` and stop at `max_rehosts` (ADR-0034); reinstalling on a known machine is free. Metadata (hostname, app and SDK version, ASCII) recorded at activation and refresh. `issue.Issuer.Sign` refuses claims of another tenant; `external_refs` values also refuse format and separator characters. New activations, deactivations and refused activations/deactivations of a known license are audited; refreshes are not.
- Member endpoints (ADR-0019, ADR-0029, ADR-0032), `internal/members`: list (cursor, newest first), `PATCH` role and product scope (JSON Merge Patch; the caller can only give or take roles it holds; the last owner can't be demoted or removed, with the tenant's owners locked in ID order), and `DELETE`, which by default revokes the API tokens the member created; a demotion or narrower scope by default revokes the member's tokens the new grant wouldn't allow (ADR-0035); `?revoke_tokens=false` keeps them; the caller's membership is re-checked inside each transaction (also in API token creation, so a token can't outlive a concurrent removal); every change, each revocation and each refusal audited.
- Platform audit chain (ADR-0027, ADR-0029): a reserved platform tenant row (`audit.PlatformTenant`, slug `platform` now taken) holds events without a tenant. `app_tenant_id()` never returns it, so the tenant and identity logins can't read or write any of its rows; no pool lists, renames, deletes or recreates it. Only the platform pool appends to it with `audit.Record`. Dashboard logins are recorded there: success (no session without its entry), a disabled user refused, and refusals of a verified ID token (nonce, claims, `azp`). `LICENSEFORGE_BOOTSTRAP_ADMIN` is now read at start: the matching user becomes platform admin at login while there is none, recorded in the same transaction; a failed bootstrap is logged and never fails the login. Migration `20261104214810_platform_tenant_security.sql`.
- Helm chart: first-class OIDC settings (`oidc.*`, ADR-0003) rendered as `LICENSEFORGE_OIDC_*`, the client secret only by `secretKeyRef`; with OIDC on, the server NetworkPolicy allows egress to the provider (`oidc.egress.port`, default 443; `oidc.egress.to`, default any address), which the deny-by-default policy blocked before, so login failed at start. `values.schema.json` checks the OIDC values; rendering fails without issuer, client ID or redirect URL.
- `compliance/` (ADR-0024): OSCAL 1.2.3 component definition of the server (NIST SP 800-53 Rev 5), control matrix, HIPAA §164.312 mapping, SSDF (SP 800-218) mapping, data inventory and Secure Configuration Guide; validated against the vendored official OSCAL schema, with cited files and tests checked, by the new `Compliance` workflow (`make compliance`). Repository `SECURITY.md` with the remediation targets. New test-only dependency in its own module: `github.com/santhosh-tekuri/jsonschema/v6`.
- Release workflow (ADR-0005, ADR-0021, ADR-0024) on `v*` tags: multi-arch (amd64, arm64) standard and `-fips` images on `ghcr.io/licenseforge/licenseforge`, Helm chart on `oci://ghcr.io/licenseforge/charts`, linux server binaries with `SHA256SUMS`; all signed keyless with cosign, with SPDX SBOM and SLSA provenance attestations (`actions/attest`). Built with a read-only token, published by separate jobs; PRs touching the release inputs run the build as a dry run. The image build cross-compiles instead of emulating arm64. How to verify: `docs/verifying-releases.md`.
- Admin dashboard scaffold (ADR-0020) in `web/`: React + TypeScript + Vite, TanStack Router and Query, shadcn/ui with Tailwind; `/login`, an app shell that loads `GET /auth/session` (401 redirects to `/login`), user menu with logout (`POST /auth/logout` with `X-CSRF-Token`), a stubbed tenant switcher and `/t/{slug}/` overview, dark mode (system or chosen), English message catalogue. Package `web` serves the bundle at `/` with SPA fallback (never for `/api/`, which answers `application/problem+json` 404, `/auth/`, `/healthz` or `/readyz`), mounted as a method-less catch-all so method-less subtrees such as `/api/v1/` can coexist, with the mux's 405s kept (a request for a path routed only for other methods, like `GET /auth/logout`, gets 405 with `Allow`, as problem JSON under `/api/`), immutable caching for hashed assets, `no-cache` with an ETag for `index.html`, a strict CSP, `nosniff` and `Referrer-Policy: same-origin`. The bundle is embedded with `make web build TAGS=webui`; without the tag (no Node) a placeholder page is served and the server logs a warning. New `Web` CI workflow: lint, typecheck, vitest, build and the Go handler test against the built bundle.
- `internal/licenses` (ADR-0013, ADR-0015, ADR-0025): issue a license from a plan, copying the plan's terms and features plus per-license overrides checked against the product's feature catalog (type, range, unknown and archived features refused), so later plan edits never change it; expiry from issue (calendar months clamped to the month's end) or unset until first activation; a new key stored only encrypted with its lookup hash and hint, returned once. Suspend, reinstate and revoke (final) with row-locked, guarded, row-counted updates. Checks in ADR-0032's order: object lookup under the product scope (a hidden product answers like a missing one; a hidden license is not found), then `license:issue` / `license:write`. Times from the database clock; `external_refs` validated; every change (with what was granted) and refusal audited.
- Signing key operations are audited (ADR-0019, ADR-0026, ADR-0027): `signing_key.create`, `signing_key.promote` and `signing_key.discard` entries with the key ID, algorithm and states (never key material), written in the same transaction as the change; denied and failed attempts are recorded after rollback in the acting principal's tenant. Key operations take the tenant's audit lock (`audit.Lock`) before any key row, the order activation uses, so a rotation under activation load can't deadlock.
- Management REST API foundation (ADR-0032): spec-first `api/openapi.yaml` (OpenAPI 3.0.3) with an oapi-codegen strict `std-http` server in `internal/api/apigen` (generated, committed, `make generate`); one outer handler for every route does the check order (exactly one credential; Bearer `lf_live_` token or dashboard session with CSRF and cross-origin checks; `{tenant}` by slug or ID; same 401 after the same work for unknown tenants and bad tokens; 404 for non-members; 403 for `sdk` tokens; `LICENSEFORGE_API_HOST` splits token and session hosts) and renders every error as RFC 9457 problem+json with `code`, `request_id` and `X-Request-Id`. First endpoints: list (cursor-paginated, newest first), create and revoke API tokens. New dependency: `github.com/oapi-codegen/runtime`.
- Repository setup, Apache-2.0 license, community files, CI.
- Architecture Decision Records 0001–0037 and the `lf1` license file format draft.
- Helm chart `deploy/helm/licenseforge` (ADR-0005): Pod Security restricted, migrations as a pre-install/pre-upgrade Job with its own Secret (serving pods never get the owner login), startup and drain-aware probes, PodDisruptionBudget, NetworkPolicies for the server and the migration Job, optional HPA; values checked at render; linted (strict) and rendered in CI.
- Container image (distroless, non-root; FIPS variant with `--build-arg GOFIPS140=certified`) and `compose.yaml` for development: PostgreSQL with `deploy/database-setup.sql`, `migrate`, then the server.
- Session middleware (ADR-0020): `weblogin.RequireSession` serves only live sessions (401 and a cleared cookie otherwise); unsafe methods need the `X-CSRF-Token` (derived from the session secret, no storage) and must be same-origin (`net/http.CrossOriginProtection`). `GET /auth/session` returns the user and CSRF token for the dashboard; `POST /auth/logout` ends the session.
- Dashboard OIDC login (ADR-0003, ADR-0020), `internal/weblogin`: Authorization Code + PKCE with state and nonce in a single-use `__Host-` cookie; the ID token is verified (signature, issuer, audience, `azp`, expiry, nonce) before `identity.Login`; every login gets a fresh session (the presented one is ended) in a `__Host-lf_session` cookie (`HttpOnly; Secure; SameSite=Lax`); `email_verified` accepted as a boolean or a string. Configured with `LICENSEFORGE_OIDC_ISSUER`, `_CLIENT_ID`, `_CLIENT_SECRET` (optional, public clients), `_REDIRECT_URL`; off when the issuer is unset; issuer and redirect URL must be https (http only on localhost); every provider call is bounded by 10 s. New dependencies: `github.com/coreos/go-oidc/v3`, `golang.org/x/oauth2` (ADR-0003).
- Server-side sessions (ADR-0020, ADR-0029): global `sessions` table (SHA-256 of the cookie, database-clock times, at most a day), `identity.NewSession` / `Session` / `EndSession` with 1-hour idle and 12-hour absolute timeouts, and `store.DB.DisableUser`, which ends every session of a suspended user in the same transaction; tenants never see sessions.
- `internal/identity` (ADR-0003, ADR-0029): `Login` creates or refreshes the user from verified OIDC claims on the identity pool (email only from a verified, usable claim; an unverified or unusable one clears the flag without blocking login; hostile names cleaned; disabled users refused; a raced first login retries), `Memberships` lists the tenant switcher, `BootstrapMatches` compares with `LICENSEFORGE_BOOTSTRAP_ADMIN` (`issuer|subject`, or a verified email).
- `internal/apitokens`: create (role-capped via `authz.CanAssign`, default 90 days, at most a year), authenticate (one query under the URL's tenant; unknown, malformed, wrong-tenant, revoked and expired tokens give the same error; use recorded DB-side at most once a minute, never failing authentication) and revoke; every change and refusal audited.
- Platform admins (ADR-0029, ADR-0031): global table managed on the platform pool, read by the login path, invisible to tenants. `DB.BootstrapPlatformAdmin` grants the first admin only while there is none and never a disabled user; `GrantPlatformAdmin` needs an enabled admin as granter and an enabled target; `RemovePlatformAdmin` refuses the last admin; all serialized on one lock. The database allows at most one bootstrap row at a time; single-statement policies back up the rest (ADR-0031).
- API tokens table (ADR-0029): role (including `sdk`), explicit product scope fixed in the creating transaction, required expiry of at most a year by the database clock, hash unique per tenant; the creator must be an owner or admin with every product (only owners create owner tokens) and the token outlives them; revocation is one-way for every role, uses are recorded only within the token's life and can't be reset; the identity login has no access.
- Identity tables (ADR-0029): `users` (global, `(issuer, subject)`), `invitations` (single-use token hash, expiry, optional issuer binding), `memberships` and product-scope tables. The database enforces that a membership is created only by accepting an open invitation, in its tenant, with its role and scope, by a user whose verified email matches (NFC, case-insensitive) and from its bound issuer, presenting the invite link's token (`DB.AcceptInvitation`, which locks the invitation so a concurrent revoke can't race it); the tenant pool can't add members, sees only its members' id, email and name, and only invites as a member; the identity pool has no access to licensing tables.
- A fourth database login, `licenseforge_login` (group `licenseforge_identity`, ADR-0029), for the login path: `LICENSEFORGE_IDENTITY_DATABASE_URL`, the `identity-database-url` Helm Secret key and a line in `deploy/database-setup.sql`. `store.Open` takes `store.Logins` and refuses any pool's login in another pool. Existing compose volumes need `docker compose down -v` to pick up the new login.
- Server with `/healthz` (liveness) and `/readyz` (fails while the database is unreachable); `licenseforge migrate` applies migrations as the schema owner. Configured by `LICENSEFORGE_DATABASE_URL`, `LICENSEFORGE_PLATFORM_DATABASE_URL`, `LICENSEFORGE_IDENTITY_DATABASE_URL`, `LICENSEFORGE_OWNER_DATABASE_URL` (migrate only) and `LICENSEFORGE_MASTER_KEYS`; the server refuses to start without them, with unsafe database logins, or with the owner login in its environment. On SIGTERM it fails readiness and drains for `LICENSEFORGE_DRAIN` (default 5s) before closing.
- `Merge gate` check: fails while a PR has the `do-not-merge` label.
- Server data layer foundation (`internal/store`): ent with PostgreSQL, prefixed IDs, versioned migrations with a built-in runner (checksums, per-file transactions, advisory lock), a role model of separate logins (owner, tenant pool, platform pool; identity pool added by ADR-0029) with forced row-level security and release-blocking isolation tests, and `deploy/database-setup.sql`; tenants and products tables.
- `internal/secrets` (ADR-0025): keyring of master keys from `LICENSEFORGE_MASTER_KEYS` (generate one with `openssl rand -base64 32`), AES-256-GCM encryption bound to its row, HMAC lookup hashes that survive key rotation.
- `internal/licensekey`: license keys `LF-` + 128 random bits in grouped base32, normalised input with one canonical spelling.
- `internal/authz` (ADR-0019): built-in roles owner/admin/manager/support/viewer and the token-only sdk role, mapped to fixed permissions; `Require` per handler, explicit product scope (zero scope denies), `Products` for list filters, `CanAssign` for member and token changes; scoped principals can't manage access; only owners grant, change or remove owner; tenant settings are owner-only.
- `internal/apitoken`: API tokens `lf_live_` + 256 random bits + CRC-32 checksum (secret-scanner friendly), offline format check, SHA-256 lookup hash and a display prefix.
- Audit log: one hash-chained, append-only chain per tenant, written in the action's transaction and serialized per tenant; `Verify` detects changed, removed or reordered entries (ADR-0027).
- Per-tenant Ed25519 signing keys with a pending → active → retired lifecycle; private keys encrypted with the master keyring and erased from the live table on retirement; `Signer` interface with a local implementation (ADR-0026).
- License invariants: term licenses always have an expiry, site licenses start at issue with no activation limit, limits are fraction-free integers with key-format names.
- Customers, licenses and activations tables (ADR-0013): plan snapshot (incl. binding policy) and resolved entitlements checked like the license format, encrypted key with per-tenant lookup hash, status and expiry invariants (expiry derived), activations bound as the license requires, one active activation per machine, never deleted, same-tenant keys and forced RLS; plans gain a binding policy.
- Catalog tables (ADR-0015): features, plans (calendar-month or second terms) and plan features; keys, slugs and types immutable and rows archived, never deleted, enforced by column-level grants; database-enforced formats and ranges; same-tenant/same-product/type composite keys; schema-vs-migration and same-tenant structural guard tests.
- Go SDK module `licenseforge.io/licenseforge/sdk/go` with `licensefile`: sign and verify `lf1` licenses (Ed25519, key ID in the envelope, algorithm bound to the trusted key).
- `lf1` conformance vectors in `spec/vectors/lf1.json`.
- `internal/issue`: signed offline license files for site licenses (air-gapped installs): `activation:offline` on the product, active and unexpired license with offline allowed, the tenant's active key, expiry rounded down, and an audit entry (`license.offline_file`) written before the file is returned; denied and failed attempts are audited too. The server module now uses the Go SDK module (`replace => ./sdk/go`, ADR-0023).
- `licensefile.Encode`: writes the lf1 payload for issuers and refuses claims that `ParseClaims` wouldn't read back identically (no rounding, no silently dropped fields).
- `licensefile.ParseClaims`, `Claims.Check` and `Open`: parse and check lf1 claims (version, product, binding, clock skew, not-before, max offline, expiry with grace, updates_until) in the order defined by the spec.
- Claim conformance vectors in `spec/vectors/lf1-claims.json` (98 cases); fingerprint derivation vectors in `spec/vectors/fingerprint.json`.
- `Entitlements.HasFeature`, `Limit` and `Allows` (ADR-0015): unknown keys are never an error; an absent limit behaves as 0; `Allows` takes the resulting total and rejects negative values.
- Go SDK `clock` package: clock rollback protection (ADR-0018): HMAC-authenticated high-water mark, `Now`/`Observe`/`Reset`, 24h default tolerance (0 = strict), rollback check that always runs (also on read-only storage), and a `FileStore` with OS file locks that is atomic and safe across processes.
- CI runs the SDK's OS-specific tests on Windows only; macOS returns with a self-hosted runner (darwin is still type-checked by `make vet-cross`).
- CI runs tests in FIPS 140-3 mode (`GOFIPS140=certified`).
- Go SDK `fingerprint` package: default machine/cluster fingerprints (vendor override, opt-in `LICENSEFORGE_FINGERPRINT`, Kubernetes kube-system UID with retries, Linux machine-id with tmpfs and container safeguards, Windows MachineGuid, macOS IOPlatformUUID), hashed per tenant and product.
